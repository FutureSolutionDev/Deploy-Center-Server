# 🚀 v3.0 — Foundation

> **Theme:** نصلح الديون التقنية + ميزات سريعة عالية القيمة
> **Status:** 🟡 Active Development
> **Target Date:** 2026-06-25
> **Duration:** 4-5 أسابيع
> **Features Count:** 10

---

## 1. Goals

1. **حل أكبر 3 ديون تقنية**: Queue persistence + Tests + Env Encryption
2. **تجهيز الـ infrastructure** للنسخ القادمة (CI, logging foundations)
3. **مكاسب UX سريعة**: Templates + Workspaces + Rollback UI + Notifications
4. **صفر breaking changes** لمستخدمي v2.1

## 2. Why This Version First?

| الديْن التقني | تأثيره الحالي | الحل في v3.0 |
|----------------|----------------|----------------|
| QueueService in-memory | restart السيرفر = ضياع كل deployments المعلقة | F-001 (BullMQ + Redis) |
| لا اختبارات | كل تعديل خطر على الإنتاج | F-002 (Testing Foundation) |
| Env Vars غير مشفرة | DB passwords، API keys مكشوفة | F-003 (AES-256-GCM) |
| Discord فقط للنوتيفيكيشن | فريق ما يعرف عن الفشل بسرعة | F-006 (Slack + Email) |
| لا Rollback UI | الـ logic موجود لكن غير مستخدم | F-007 (Rollback UI) |

**القاعدة:** بدون هذه، أي feature جديدة في v3.1+ ستُبنى على رمال.

## 3. Features in Scope

### 🔴 F-001 — BullMQ + Redis Persistent Queue (P0, L)

**المشكلة:**
`QueueService` حالياً يستخدم `Map<projectId, Item[]>` في الذاكرة. أي restart للسيرفر = ضياع كل deployments المعلقة بدون إشعار.

**الحل:**
- استبدال `Services/QueueService.ts` بـ wrapper حول BullMQ
- إضافة `Config/RedisConfig.ts` مع env vars: `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD`, `REDIS_DB`
- Bull Board admin dashboard على `/admin/queues` (admin role only)
- Job retry: 3 محاولات، exponential backoff (1s → 5s → 25s)
- Migration path: عند upgrade، يُقرأ جدول `Deployments` للحالة `Pending` ويُعاد جدولتها

**Models / Migrations:**
- Migration `012_add_queue_job_id_to_deployments.ts`:
  - إضافة `Deployment.QueueJobId VARCHAR(100) NULL`
  - Index: `idx_deployments_queue_job_id`

**Dependencies:**
- `bullmq` (~5.x)
- `ioredis` (~5.x)
- `@bull-board/api` + `@bull-board/express` (للـ dashboard)

**Acceptance Criteria:**
- [ ] إعادة تشغيل السيرفر لا تفقد deployments المعلقة
- [ ] Bull Board dashboard متاح فقط لـ admin
- [ ] Failed deployments تُعاد محاولتها 3 مرات قبل الفشل النهائي
- [ ] Tests: 6 unit + 2 integration

**Effort:** 5-7 أيام

### 🔴 F-003 — Encrypted Environment Variables (P0, M)

**المشكلة:**
المفاتيح الحساسة موجودة في `Project.Config` JSON بدون تشفير. أي SQL injection = exposure.

**الحل:**

**Model جديد:**
```typescript
// server/src/Models/EnvironmentVariable.ts
class EnvironmentVariable {
  Id: number;
  ProjectId: number;        // FK → Projects.Id, CASCADE
  KeyName: string;          // VARCHAR(100), Not Null
  ValueEncrypted: string;   // TEXT — AES-256-GCM
  Iv: string;               // VARCHAR(32)
  AuthTag: string;          // VARCHAR(32)
  IsSecret: boolean;        // يخفي القيمة في UI
  CreatedAt: Date;
  UpdatedAt: Date;
}
```

**Migration `009_create_environment_variables.ts`:**
- جدول `EnvironmentVariables` كما أعلاه
- Index: `(ProjectId, KeyName)` UNIQUE

**Service:**
- `Services/EnvironmentVariableService.ts`
- استخدام `Utils/EncryptionHelper.ts` (موجود فعلاً للـ SSH)
- Methods: `Create`, `GetAllForProject`, `Update`, `Delete`, `Decrypt`

**API:**
```
GET    /api/projects/:id/env-vars        # List (values masked if IsSecret)
POST   /api/projects/:id/env-vars        # Create
PUT    /api/projects/:id/env-vars/:key   # Update
DELETE /api/projects/:id/env-vars/:key   # Delete
```

**في الـ Pipeline:**
- عند `spawn()` في `PipelineService`، تُحقن المتغيرات في `process.env`
- لا تُكتب في الـ log file (مفلترة)

**UI:**
- Tab جديد في Project Details: "Environment Variables"
- قائمة Key/Value مع زر "Show" للـ secrets

**Acceptance Criteria:**
- [ ] Env vars مُشفّرة في DB
- [ ] `.env` ملف لا يحتوي قيم plain
- [ ] Pipeline يحقنها صحيحاً
- [ ] Secrets لا تظهر في logs أو errors
- [ ] Tests: 4 unit + 2 integration

**Effort:** 3-4 أيام

### 🔴 F-005 — Local Git Bare Cache (P0, S)

**المشكلة:**
كل deployment يعمل `git clone` كامل من scratch. لمشروع كبير = 30+ ثانية لكل deploy + استهلاك مساحة.

**الحل:**
- مجلد جديد: `server/deployments/cache/project-{id}.git/` (bare repo)
- في `DeploymentService.PrepareRepository()`:
  ```
  if (cache exists) {
    git -C cache fetch --all --prune
    git clone --reference cache --dissociate <repo> <deploy_path>
  } else {
    git clone --bare <repo> cache
    git clone --reference cache --dissociate <repo> <deploy_path>
  }
  ```
- توفير: ~85% وقت + ~70% disk

**Acceptance Criteria:**
- [ ] أول deploy: يبني الـ cache + يستخدمه
- [ ] الـ deploys اللاحقة: تستخدم الـ cache (verify with file timestamps)
- [ ] Cache يُحدّث قبل كل deploy (`git fetch`)
- [ ] تنظيف cache بعد حذف المشروع (CASCADE)
- [ ] Test unit واحد للـ logic

**Effort:** 2 أيام

### 🟡 F-006 — Multi-Channel Notifications (P0, M)

**المشكلة:**
Discord فقط. الفرق التي تستخدم Slack أو Email لا تتلقى إشعارات.

**الحل:**

**Refactor `NotificationService` إلى Strategy Pattern:**
```typescript
interface INotificationChannel {
  Send(payload: INotificationPayload): Promise<void>;
}

class DiscordChannel implements INotificationChannel { ... }  // موجود
class SlackChannel implements INotificationChannel { ... }    // جديد
class EmailChannel implements INotificationChannel { ... }    // جديد (nodemailer موجود في deps)
```

**Model جديد:**
```typescript
class NotificationChannel {
  Id: number;
  ProjectId: number | null;     // null = global
  Type: 'discord' | 'slack' | 'email';
  Name: string;
  ConfigEncrypted: string;      // webhook URL or SMTP creds
  Iv, AuthTag: string;
  Events: string[];             // JSON: ['deployment.started', 'deployment.failed', ...]
  IsActive: boolean;
}
```

**Migration `013_create_notification_channels.ts`**

**API:**
```
GET    /api/notifications/channels
POST   /api/notifications/channels
PUT    /api/notifications/channels/:id
DELETE /api/notifications/channels/:id
POST   /api/notifications/channels/:id/test  # send test message
```

**UI:**
- Settings → Notifications tab
- اختيار Type → form ديناميكي حسب النوع
- زر "Test Notification"

**Acceptance Criteria:**
- [ ] Slack webhook يُرسل بنفس formatting الـ Discord
- [ ] Email يستخدم HTML template جميل
- [ ] Test notification يصل خلال 5 ثوانٍ

### 🟡 F-007 — Rollback UI + Service Hardening (P0, S)
