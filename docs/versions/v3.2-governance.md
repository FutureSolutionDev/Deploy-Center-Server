## 2. Features in Scope

### 🔴 F-022 — Approval Workflow (P0, M)

**Project additions:**
- `RequireManualApproval` BOOLEAN DEFAULT false
- `ApprovalRoles` JSON — قائمة roles المسموح لها بالموافقة

**Deployment additions:**
- `ApprovedBy` INT NULL (FK → Users)
- `ApprovedAt` DATETIME NULL
- Status جديد: `EDeploymentStatus.AwaitingApproval`

**Workflow:**
- Webhook/manual trigger → status = AwaitingApproval (لا يدخل queue)
- Notification لـ approvers
- Approver يضغط Approve → status = Queued → ينفّذ
- Reject → status = Rejected

**Migration `014_add_approval_to_deployments.ts`** (يجمع projects + deployments)

**Effort:** 3 أيام

---

### 🔴 F-023 — Manual Visual Diff (P0, L)

**المشكلة:** قبل approval، الـ approver يحتاج يرى ما الذي تغيّر.

**الحل:**
- يقارن commit الـ deployment الحالي مع آخر deployment ناجح
- يستخدم GitHub/GitLab API لجلب diff (مكتبة `octokit` للـ GitHub)
- UI: split view (before/after) + syntax highlighting (مكتبة `prismjs`)
- Files filter: hide `node_modules`, `dist/`, lockfiles

**Effort:** 5-6 أيام (UI معقد)

---

### 🔴 F-024 — Resource Quotas (CPU/RAM) (P0, L)

**المشكلة:** Pipeline ضخم ممكن يستهلك السيرفر كله.

**Project additions:**
- `MaxCpuPercent` INT NULL (e.g. 50 = 50% CPU)
- `MaxMemoryMb` INT NULL (e.g. 2048 = 2GB)

**Implementation:**
- **Linux:** cgroups v2 (cgcreate + cgexec) أو systemd-run
- **Windows:** Process priority + `Set-ProcessMitigation` للـ working set
- **Watchdog:** كل 5 ثوانٍ يفحص process usage → kill لو تجاوز

**Migration `018_add_resource_quotas_to_projects.ts`**

**Acceptance:** أداء consistent، لا يكسر السيرفر

**Effort:** 5-6 أيام (cross-platform)

---

### 🔴 F-025 — Artifact Retention Policy (P0, S)

**المشكلة:** logs و deployment files تتراكم بلا حدود.

**Project additions:**
- `RetentionDays` INT DEFAULT 30 (deployments أقدم من هذا → حذف logs only، الـ DB records تبقى)
- `MaxDeployments` INT DEFAULT 100 (هارد limit للـ project)

**Cron job يومي (موجود via `node-cron`):**
- يحذف ملفات `deployments/{id}.log` للـ deployments أقدم من RetentionDays
- يحذف ملفات artifacts (build outputs cached)

**Effort:** 1-2 يوم

---

### 🟡 F-026 — User-Defined Metrics (P1, M)

**المشكلة:** كل مشروع له metrics مختلفة (response time, error rate, ...).

**الحل:**
- Project additions: `CustomMetrics` JSON
- Format: `[{ name, url, threshold, alarm_below_above }]`
- بعد deployment، يجمع المقاييس + يحفظ في `DeploymentMetrics` جدول جديد
- UI: charts via Recharts (موجود)

**Effort:** 3-4 أيام

---

### 🟡 F-027 — Custom Scripts Hooks (P1, M)

**المشكلة:** المستخدمون يحتاجون hooks بسيطة بدون تعديل pipeline كامل.

**الحل:**
- Project additions: `PreDeployHook` TEXT, `PostDeployHook` TEXT
- يُنفذ قبل/بعد الـ pipeline (نفس shell session)
- Variables متاحة: `$DEPLOY_ID`, `$COMMIT_HASH`, `$BRANCH`

**Effort:** 2 أيام

---

### 🟡 F-028 — Multiple Rollback Points (P1, M)

**المشكلة:** Rollback لآخر deployment فقط أحياناً غير كافٍ.

**الحل:**
- UI: قائمة آخر 10 deployments ناجحة + زر "Rollback to this"
- يستخدم infrastructure من F-007
- لا snapshots على disk — git commit hash كافٍ

**Effort:** 2 أيام

---

### 🟡 F-029 — Audit Log Search UI (P1, M)

**المشكلة:** الـ audit logs موجودة لكن لا UI للبحث.

**الحل:**
- Search page جديدة: `/audit-logs`
- Filters: user, action, resource type, date range
- Export to CSV
- Pagination + sorting

**Effort:** 2-3 أيام

---

### 🟡 F-030 — Configuration Schema Validator (P1, M)

**المشكلة:** Project Config (Pipeline JSON) ممكن يكون malformed.

**الحل:**
- استخدام Joi (موجود في deps) لـ validate `Project.Config`
- Schema definitions في `Types/ProjectConfigSchema.ts`
- Validate عند save + قبل deployment

**Effort:** 2 أيام

---

### 🟡 F-031 — Dry-Run Simulation (P1, M)

**المشكلة:** اختبار pipeline بدون تأثير = نقص خطير.

**الحل:**
- API: `POST /api/projects/:id/dry-run`
- ينفذ كل خطوة لكن:
  - لا writes للـ disk الفعلي
  - SFTP/SSH = list-only (لا upload/execute)
- ينتج report: ما الذي **سيُنفّذ**

**Effort:** 3-4 أيام

---

### 🟡 F-032 — Automatic DB Backups (P1, M)

**المشكلة:** نشر يحتوي migrations = خطر لو فشل.

**الحل:**
- Project additions: `BackupCommand` TEXT (مثل `mysqldump ...`)
- يُنفّذ تلقائياً قبل deployment لو الـ pipeline يتضمن migrations
- يُحفظ في `backups/{projectId}/{timestamp}.sql`
- Retention مع F-025

**Effort:** 3 أيام

---

### 🟢 F-033 — Credential Rotation (P2, M)

**المشكلة:** SSH keys و API tokens لا تُجدَّد = خطر أمني.

**الحل:**
- Cron job: يفحص آخر rotation date
- بعد X أيام (configurable): يُولّد credential جديد، يبقي القديم لمدة grace period
- Notification بالـ rotation

**Effort:** 3 أيام
