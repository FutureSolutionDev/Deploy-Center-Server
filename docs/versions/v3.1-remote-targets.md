### 🔴 F-012 — SFTP Smart Sync (P0, L)

**المشكلة:** نشر كامل = رفع كل الملفات (بطيء + مكلف bandwidth).

**الحل:**
- مكتبة: `ssh2-sftp-client`
- Algorithm:
  1. List remote files (recursive)
  2. Calculate local file hashes (MD5 sufficient لـ change detection)
  3. Compare → upload only changed/new files
  4. Delete remote files المفقودة محلياً (مع احترام `systemPreservePatterns`)
- Parallel uploads (4-8 streams)
- Progress events عبر Socket.IO

**Acceptance Criteria:**
- [ ] أول deploy: رفع كامل
- [ ] الـ deploys اللاحقة: رفع الـ diff فقط
- [ ] الملفات في `systemPreservePatterns` لا تُحذف
- [ ] Test على Hostinger sandbox

**Effort:** 5-6 أيام

### 🔴 F-013 — SSH Post-Deploy Scripts (P0, M)

**المشكلة:** بعد رفع الملفات، نحتاج restart للـ service (PM2/systemd/nginx).

**الحل:**
- استخدام `ssh2` library
- تنفيذ `PostDeployScript` من DeploymentTarget عبر SSH session
- Stream output لـ deployment log (نفس formatter)
- Timeout: 5 دقائق (configurable)
- فشل الـ script = فشل الـ deployment

**Examples:**
```bash
# Node.js with PM2
pm2 restart ecosystem.config.js --update-env

# Nginx reload
sudo nginx -s reload

# Docker
docker compose up -d --build
```

**Effort:** 2-3 أيام

### 🔴 F-015 — Auto-Rollback on Health Check Failure (P0, M)

**المشكلة:** Health Check بدون rollback = نشر فاشل في production.

**الحل:**
- لو Health Check فشل بعد X retries:
  1. يُنشئ deployment جديد type=rollback لآخر deployment ناجح
  2. ينفّذه فوراً (priority عالي)
  3. ينتظر Health Check مرة ثانية على الإصدار القديم
  4. لو نجح → notify فريق بـ "Auto-rolled back"
  5. لو فشل أيضاً → emergency alert (Slack + Email)
- يستخدم F-007 (Rollback infrastructure)

**Acceptance Criteria:**
- [ ] Health Check فاشل → rollback يبدأ خلال 30 ثانية
- [ ] الـ rollback نفسه له health check (لمنع loops)
- [ ] Notification يصل لكل قنوات الـ project

**Effort:** 2-3 أيام

### 🟡 F-016 — Let's Encrypt SSL Automation (P1, L)

**المشكلة:** SSL يدوي = صداع + مخاطر انتهاء.

**الحل:**
- مكتبة: `acme-client`
- API: `POST /api/targets/:id/ssl/provision`
- Verification: HTTP-01 (للـ VPS مع port 80 مفتوح) أو DNS-01 (Cloudflare API)
- Cron يومي: يفحص الشهادات، يجدد قبل انتهائها بـ 30 يوم
- النشر التلقائي للشهادة الجديدة عبر SSH

**Acceptance Criteria:**
- [ ] إصدار شهادة جديدة لـ domain
- [ ] التجديد التلقائي يعمل (test بـ short-lived cert في staging)
- [ ] فشل التجديد = notification

**Effort:** 4-5 أيام

### 🟡 F-017 — Project Clone (P1, S)

**المشكلة:** إنشاء مشاريع متشابهة يدوياً = تكرار.

**الحل:**
- API: `POST /api/projects/:id/clone` body: `{ NewName: string }`
- ينسخ:
  - Config (pipeline + preserve patterns)
  - EnvironmentVariables (re-encrypted بنفس key)
  - DeploymentTargets (بدون credentials — تُطلب يدوياً)
  - SSH key (مفتاح جديد يُولَّد)
- لا ينسخ: deployments history, audit logs

**UI:** زر "Clone" في Project Details

**Effort:** 1-2 يوم
